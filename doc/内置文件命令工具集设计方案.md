# 内置文件 / 命令工具集设计方案

状态：**设计方案（待评审后实现）**。对应实现为独立顶层包 `builtin`（`github.com/JIAOZAI1/agent-go/builtin`，package 名 `builtin`），不归属 `tool` 子包。`web_search` 不在本方案范围。

## 1. 定位与原则

提供一个**独立的顶层 `builtin` 包**（与 `message`/`tool`/`session` 平级的可独立 import 原子包，`github.com/JIAOZAI1/agent-go/builtin`），内含三个预写好、**需使用方手动 `AddTool` 注册**的工具对象：

- `builtin.NewRead(cfg) tool.Tool` —— 读取指定文件
- `builtin.NewEdit(cfg) tool.Tool` —— 在文件中替换一段文本（或追加）
- `builtin.NewBash(cfg) tool.Tool` —— 在限定工作目录下执行命令

作为独立顶层包，它只依赖 `tool`（复用 `tool.Tool`/`tool.Result`），方向上与 `agent ──> tool` 一致：`builtin ──> tool`，无循环。

遵守既有 `工具系统设计方案.md` 的安全心智：

1. 这些只是“工具对象”，**默认不自动/隐式/全局挂载到任何 Agent**。权限授予的唯一时机是使用方在组装运行实例时显式
   `builder.AddTool(builtin.NewRead(cfg)); builder.AddTool(builtin.NewEdit(cfg)); …`。由于工具默认完全关闭，宿主只在显式注册
   时将它们放进 Agent 能力范围，安全责任属于注册方。
2. **纯标准库实现**（文件系统 + `os/exec`），零第三方运行时依赖（延续除 `session/sqlite` 外全库零依赖的姿态）。
3. 鉴权、限流、审计仍属 Middleware 职责；工具只做自身边界校验（root 包含关系、参数、输出上限、超时）。
4. 失败走 error；错误文案不回显内部路径、真实符号链接目标、临时文件路径或凭证。
5. JSON Schema 手写、类型检查用标准 `encoding/json`，不引第三方校验库。

## 3. Config（共享）

```go
// Config 界定宿主对文件系统与命令的放行范围。所有放行边界默认收敛（root 必填），
// 工具构造后可被多个并发 Execute 调用。
type Config struct {
    Root string // 放行根目录，必填；空字符串视为无效并返回构建错误。相对路径按进程 cwd 解析为绝对。

    MaxReadBytes  int64 // read 单次读取上限，0 默认 1 MiB
    EditOutputLen int   // edit 返回内容摘要长度上限，0 默认 1 KiB

    // shell 相关
    Shell   string   // Windows 下解释器；留空使用 posix 默认 ["/bin/sh", "-c"]
    WorkDir string   // bash 默认工作目录；空默认 = Root
    Env     []string // 追加 "K=V" 环境变量（可选），追加在进程 os.Environ() 之后
}
```

构造与默认：

```go
// NewRead 返回一个读取 root 树内文件的 Tool。
func NewRead(cfg Config) tool.Tool
// NewEdit 返回一个在 root 树内单处替换/追加的 Tool。
func NewEdit(cfg Config) tool.Tool
// NewBash 返回一个以 cfg.WorkDir(缺省 Root) 为工作目录执行命令的 Tool。
func NewBash(cfg Config) tool.Tool
```

- 三者闭合到同一套默认量级：read 截断点（默认 1 MiB 起读）、返回概览长度、shell 超时/输出上限，均内置 default 常量且可在各自 cfg 覆盖。为最小面，第一档把哪些字段暴露按 §3.1：

### 3.1 字段暴露与默认（写入上述类型）
- `Root`:必需放行根；空 → 构造时即返回不可用错误。
- `MaxReadBytes int64`：0⇒`defaultMaxReadBytes = 1 << 20`。
- `EditOutputLen int`：0⇒`defaultEditSummaryLen = 1024`。
- `Shell`：在非 Windows（`runtime.GOOS != "windows"`）用默认 `[]string{"/bin/sh","-c"}`；用户在 windows 通常给 `cmd /C`。实现内部 Shell 空白用 fallback posix。
- `WorkDir`：空⇒=Root。
- `Env`：nil/len0 不追加。
- signal(shell 不直接导出 extra; 需要加时后续扩展，保持窄。)

## 4. 共享根路径校验（唯一 guard）

`resolveInRoot(cfg.Root, requestPath) (string, error)`:

1. `requestPath==""` → error。
2. 相对路径视与 root 拼；绝对路径直接用；统一 `filepath.Clean`。
3. 转绝对后用**包含校验**：最终路径必须 `== root` 或以 `root + string(filepath.Separator)` 为前缀。
4. 对**已存在**的路径再 `filepath.EvalSymlinks` 解析其真实位置做同款包含校验，堵住 `..`/symlink 逃逸。
5. 不满足 → 返回包含 sentinel `builtin.ErrOutsideRoot` 的 error（文案不含真实路径/目标）。

导出：
```go
var ErrOutsideRoot = errors.New("builtin: path outside allowed root")
```

## 5. NewRead

Schema：
```json
{ "type":"object",
  "properties":{"path":{"type":"string"}},
  "required":["path"] }
```
Execute:
- `resolveInRoot` 校验 → `os.ReadFile(path)`；
- 超过 `cfg.MaxReadBytes`（默认 1 MiB）取前 n+`[…] truncated at {n} bytes` 标记；
- 有效内容写入 `Result.Content:text`。

## 6. NewEdit

Schema：
```json
{ "type":"object",
  "properties":{
     "path":{"type":"string"},
     "old":{"type":"string"},
     "new":{"type":"string"}
  },
  "required":["path"] }
```
Execute:
- `resolveInRoot` 校验；
- 读现存文件（可先略超限问题）；
- 变换：
  - `old != ""`：`content = strings.Replace(content, old, new, 1)`（只替换第一处）；
  - `old == ""`：`content += new`（追加在末尾）——采纳推荐语义；
- 若 `old != ""` 且文件中未找到该旧串：**不返回 error**，而是返回业务提示文本 `Result.Content = "old text not found; file unchanged"`，供模型自省后重试（§7 决策 2）；
- **原子写**：`os.CreateTemp(filepath.Dir(path), ".edit-*")` 写新内容 → `os.Rename(tmp, path)` 原子替换 → 失败时删临时文件避免残留；
- `Result.Content`：当新内容长度 ≤ `cfg.EditOutputLen`（默认 1 KiB）返回完整新文本预览，否则截断 + `[…]`，并注明改了 so 模型可复核。

## 7. NewBash

Schema：
```json
{ "type":"object",
  "properties":{
     "command":{"type":"string"},
     "workdir":{"type":"string"},
     "timeout_ms":{"type":"integer","minimum":1}
  },
  "required":["command"] }
```
Execute:
- `command==""` → error;
- shell 解析：`sh := cfg.Shell`；空→ `["/bin/sh","-c"]`（Windows 建议显式给 `cmd /C`，留空也回退 /bin/sh，方便类 unix）;
  - 实际使用 `[sh[0], append(sh[1:], command)...]` 组装。
- `dir := cfg.WorkDir`；若空 = `cfg.Root`。若 workdir 参数传则用该参数（作为相对 root 解析；可选，null 不回退）。
- 用 `exec.CommandContext`：
  - `cmd.Dir = dir`；`cmd.Env = append(os.Environ(), cfg.Env...)`；
  - 超时：若 `timeout_ms`>0 用之，否则默认 `defaultShellTimeout=60s`；把请求 ctx 与超时一起做 `context.WithTimeout`（若请求 ctx 更早 DeadLine 取更早者）。
- 输出：stdout+stderr 各 `bytes.Buffer`；合并到 `Result.Content` 为：
  ```
  exit=0
  ```
  采用 `OUT:\n…\nERR:\n…` 两段；各自限长合计 ≤ `defaultMaxShellOutput=64 KiB`，超则截断加 `[… truncated]`。
- 退出码非 0：不 error 化——返回业务结果 `exit=$code` 并附输出（模型可见其原因自行修正），仅启动失败 / 超时 / ctx 取消才回 error。

## 8. 安全与责任边界（写入 doc 与 README）

- 默认任何 Agent 都拿不到这些工具，只在使用方显式 `AddTool` 时进入能力域。
- `read`/`edit` 默认限定 `cfg.Root` 内（防 `..`/symlink 逃逸）。
- `bash` 默认以 `Root/WorkDir` 为工作目录，但**不承诺 OS 级沙箱**：`cd`、管道、环境内任意命令都可能逃出 root；真正隔离靠容器/OS（unshare、容器）。是否把 `NewBash` 授予某个 Agent，由使用方决定并负责，项目建议以容器/沙箱承载真正需要的进程级执行。
- 结果大小统一上限、超时默认、截断标记，避免把大文件/大输出塞进模型上下文。
- 不打印内部凭据/真实路径。

## 9. 测试策略

- **root 包含关系**：root 内正常读；`../a`、绝对到 root 外、symlink 指向 root 外 → `ErrOutsideRoot`；缺 path error。
- **read**：读普通文本；超 `MaxReadBytes` 截断+标记；读不存在/目录 error。
- **edit**：替换第一处正确；`old==""` 追加生效；找不到 `old` 返回提示文本(non-error)；写走后读回一致；目录下无 `.edit-*` tmp 残留；越界拒。
- **bash**：posix 默认 `sh -c` 在 root/WorkDir 内跑；out/err 合并含 `OUT/ERR` 段与 `exit`;`timeout_ms` 与默认超时触发后结束并提示；ctx 取消回 error；非 0 退出返回业务结果。
- **并发**：多 goroutine 调同一实例（-race，需含 gcc 环境）。
- 全量 `gofmt / go vet ./... / go test ./...`。

## 12. 关键决策总结

1. 独立顶层 `builtin` 包（package `builtin`，`…/agent-go/builtin`），不放入 `tool` 子包，以保持其作为通用工具集的原子可独立 import 性。
2. edit `old==""` 采用“追加到末尾”语义。
3. edit 找不到旧串返回“old text not found; file unchanged”业务提示文本（不放 error），便于模型重试——与工具循环 `StopOnToolError=false` 默认继续契合。
4. bash 默认工作目录取 `cfg.WorkDir` 空则 `cfg.Root`；工具不强沙盒，真正隔离 = 容器/OS，doc/README 明示并由真正授予方使用方负责。
5. （注：web_search 不在本方案，后续若启动另出独立设计。）
