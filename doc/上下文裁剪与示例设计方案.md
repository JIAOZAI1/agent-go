# 上下文裁剪（trim）与可运行示例设计方案

## 1. 背景与问题

`agent-go` 的 ToolLoop 早期文档反复把“无上下文裁剪、长对话 + 多轮工具可能超出模型 context window”列为当前唯一明显缺陷，长期只靠 `MaxTurns` 兜底。本方案补齐**一个用于给送入模型的会话历史做有界裁剪的轻量组件**，并把一条可离线运行的 `examples` 演示加入仓库，作为对外发布库可即用证据。

本文件记录该组件的落地形态与一处与早期草案不同的实现决策（预算来源），便于追溯。

## 2. 目标 / 非目标 / 约束 / 成功标准

### 目标
- 新增 `trim` 包：提供 `message` 字节大小的启发式度量与一个“保留最近会话、逐旧丢弃至预算内”的无状态裁剪器，供 Agent 编排在 `Load` 之后、组装模型请求之前裁剪本次加载的历史。
- 把裁剪作为一个**可选的运行能力**接入 `ToolLoopAgent`（`ToolLoopOptions`/`RunEnv` 新增字段），保留 `nil`=不裁剪的现状（零迁移）。
- 提供一个完全离线可 `go run` 的工具循环示例 `examples/weather_agent`，演示 Session、工具(+中间件)、Fanout 事件与 RunStats 的组合。

### 非目标
- 不做消息摘要/压缩回填、不做持久 Session、不改任何既有公开接口语义。
- 不做精确按厂商 tokenizer 的 token 级估算；`trim` 以**字节**为预算单位并保留注入更精确估算器的扩展位，而非把复杂度放进核心。
- 不新增第二套“Chain/Composite 裁剪器”；多策略组合留待出现真实需求再评估。

### 约束
- `trim` 只依赖 `message`，不反向依赖 `agent`（避免循环依赖；`agent→trim→message` 是单向叶子链）。
- 裁剪只针对 **Load 出来的历史快照**，不写回 Store——与既有 Session 设计文档一致。
- `ToolLoopAgent`、`RunEnv` 新增字段均为可选注入，不改变既有测试调用形态。

### 成功标准
- 超长会话注入裁剪器后，Executor 实际收到的历史被限在预算内、当前输入始终保留、非空。
- 无裁剪器时历史原样（既有路径零回归）。
- `gofmt` / `go build ./...` / `go vet ./...` / `go test ./...` 全绿；`-race` 需在含 gcc/CGO 的 Linux CI 上执行（本地无 gcc 无法跑，属既有工具链限制）。

## 3. 设计与接口

### 3.1 度量与裁剪器（`trim` 包）

```go
package trim

// Trimmer 把一个已加载的会话快照裁剪到适合送入模型的规模。
// 必须为纯函数：输入传入隔离快照，不得保留或改动；兼容并发调用。
type Trimmer interface {
    Trim(current []message.Message, budget int) []message.Message
}

// TrimmerFunc 适配普通函数到 Trimmer；nil 视为 no-op 原样返回。
type TrimmerFunc func(current []message.Message, budget int) []message.Message

// SizeOf 报告消息内容的字节大小（文本/图片 URL 与 data/tool-call 名与实参）。
func SizeOf(m message.Message) int

// KeepRecent 返回 current 的尽量长的“最近后缀”，从最旧端逐条丢弃，
// 使 SizeOf 累积不超过 budget；current 非空时至少保留最新一条，故结果永非空。
func KeepRecent(current []message.Message, budget int) []message.Message

// NewKeepRecent() Trimmer 是可供 Agent 直接注入的默认裁剪策略。
```

`KeepRecent` 复用底层切片（返回 `current[start:]`），避免复制；编排侧随后再 `message.CloneSlice` 才拼进请求，因此数据不共享、无污染。

### 3.2 接入 ToolLoop

`RunEnv` 与 `ToolLoopOptions` 各新增可选字段：

```go
Trimmer   trim.Trimmer // nil = 不裁剪（现状行为）
TrimBudget int         // >0 时作为裁剪预算（字节）；否则用默认兜底
```

构造期通过私有辅助解析出不可变 `a.trimmer` 与 `a.trimBudget`。`Run` 在 `Store.Load` 成功后、组装 `history` 前插入：

```go
if a.trimmer != nil && a.store != nil {
    snapshot.Messages = a.trimmer.Trim(snapshot.Messages, a.trimBudget)
}
```

裁剪只影响本次 `Run` 的快照，Store 不被写入；后续 `commit` 仍把“本轮新增”按原 batch 提交，旧历史的不裁剪版本仍完整留在 Store 中——即裁剪是**只读的面向请求层的窗口化**，不破坏 Session 的记录完整性。

### 3.3 预算默认值（与早期草案的一处差异）

早期草案建议“默认读取 `Executor.Model().ContextWindow`”。落地时发现**当前公开契约 `model.Executor.Model()` 只返回 `model.Ref`（ProviderID+ModelID），并不携带 `ContextWindow`**（该字段在 `model.Model`，而 Executor 绑定的是 `Ref`）。为避免为读取窗口而改动 `Executor` 接口（破坏性、非真实需求驱动），改为：

```go
const trimHistoryDefaultBytes = 8192

func trimBudget(trimmer trim.Trimmer, explicit int) int {
    if trimmer == nil { return 0 }        // 未配置裁剪 → 禁用
    if explicit > 0 { return explicit }   // 优先显式 TrimBudget
    return trimHistoryDefaultBytes        // 兜底，保证显式 Trimmer 仍裁剪
}
```

即：预算以显式 `TrimBudget` 为权威；未设置时用 8192 字节兜底，让带假 Executor（窗口为 0）的测试与 examples 仍可确定运行。文档明确建议生产部署按自身模型窗口换算 `TrimBudget`（字节级启发式，token 级精确估算不作为 v1 目标）。

## 4. 可运行示例 `examples/weather_agent`

主 module 内的 `package main`（可直接 `go run`，离线、无需真实 API `Key`）：

- 用 `session.MemoryStore` 持有会话历史；
- `tool.NewBuilder` + 一个演示 `weatherTool` 与 `logToolMiddleware`；
- 一个离线的 scripted `model.Executor`（首次 Generate 返回一次 `get_weather` 工具调用，重入后返回最终 stop 文本），把真实厂商差异隔离在 executor 一处；
- `agent.NewFanoutSink` 订阅打印 `run.* / model.* / tool.*` 事件流；
- `ToolLoopAgent` 跑通并打印 `RunStats` 与会话 revision。

README 注明：换真实模型只需把脚本式 executor 换成 `provider/openai.NewExecutor`，其余组合不变。

## 5. 兼容与演进

- 新增包 `trim`（净新增导出，不占既有名字）；`RunEnv`/`ToolLoopOptions`/`ToolLoopAgent` 为新增可选字段/构造收口，不改动任何既有调用形态。
- `examples/weather_agent/main.go` 为独立 `package main`，不会进入库的导入面；`go test ./...` 对其显示 `[no test files]`。
- 演进位：若日后 `Executor`/能力承载显著变化并确有“按窗口自动裁”需求，可把预算来源改回窗口并由 `Executor` 声明窗口；摘要/分类/加密等更复杂裁剪留待真实需求。

## 6. 测试策略

- `trim`：`SizeOf`（文本/空/图片/tool-call）、`KeepRecent`（空、未超限原样、逐旧丢弃、恰好等于预算、单条即超限仍保最新、大历史有界且保最新）、`TrimmerFunc` nil no-op、`NewKeepRecent` 有界。
- `agent` 集成：注入裁剪器后 Executor 侧历史受限且末尾为本轮输入；无裁剪器时历史全量；未显式预算时用兜底仍裁剪。
- 全量 `gofmt` / `go build` / `go vet` / `go test`；`-race` 在含 gcc 环境执行（见成功标准）。
